# Отчёты по backend: практические работы № 5–28

## Практическая работа № 23. Производительность и кэширование

### Сценарий и условия

Измеряется `GET /api/vacations?search=PERF-&archived=false&page=0&size=100` на локальном PostgreSQL с 10 000 подготовленных записей. Скрипт делает 5 прогревочных и 100 измеряемых запросов, не выводит access token и сообщает p50/p95. Seed запускается только на локальной демонстрационной БД и удаляет перед заполнением записи с префиксом `PERF-`.

Подготовка и замер (команды из `backend/`):

```powershell
Get-Content .\scripts\performance-seed.sql -Raw | docker compose exec -T postgres psql -U vacatime -d vacatime
$env:VACATIME_ACCESS_TOKEN = '<access token>'
.\scripts\benchmark-vacation-search.ps1
```

**Результат:** замер в этой среде не выполнен: Docker и PostgreSQL-клиенты недоступны. До получения замера не добавлялись кэш и новые индексы. Целевой критерий для учебного стенда — p95 не более 2 секунд; сравнение и решение об оптимизации нужно заполнить после запуска на одном и том же стенде до/после.

### Архитектурное решение

Выбранный вариант — модульный монолит Spring Boot: один REST API, единый PostgreSQL и слои controller/service/repository. По сравнению с микросервисами он не требует сетевых контрактов и согласованного развёртывания нескольких компонентов; по сравнению с отдельным серверлесс-набором проще локально воспроизводится вместе с Liquibase. При текущем объёме API и учебной команде переход на распределённую архитектуру не даёт оправданной пользы.

Технический долг backend: нет выполненного PostgreSQL benchmark и теста восстановления backup; Compose-конфигурация пока предназначена для localhost, не для внешнего хостинга. Политика доступа сейчас ролевая; фильтрация данных по подразделению или отдельному сотруднику потребует отдельного требования.

### Модель угроз и меры

| Актив/риск | Мера в backend | Статус |
|---|---|---|
| Подбор пароля | BCrypt, блокировка после серии неудачных входов | Проверяется интеграционными тестами. |
| Кража/повтор refresh-token | В БД хранится хэш; refresh/logout отзывает сессию | Покрыто тестами аутентификации. |
| Повышение привилегий | Проверки ролей на серверных endpoints | VIEWER/EDITOR/ADMIN проверяются тестами. |
| Утечка JWT-secret и паролей БД из Git | Обязательный `JWT_SECRET`; локальный `.env` игнорируется Git | Настроено; секреты на реальном сервере не проверялись. |
| Сетевой доступ к локальной БД/API | Порты Compose опубликованы только на `127.0.0.1` | Настроено; Compose не запускался в этой среде. |
| Утечка данных через ошибки и логи | Ошибки API возвращают безопасные сообщения, correlation ID не содержит токен | Проверяется тестами/инспекцией; отдельный внешний security-аудит не выполнялся. |
| Потеря/недоступность БД | Инструкция `pg_dump`/`pg_restore`, volume и health endpoint | Подготовлено; реальное восстановление ожидает Docker/PostgreSQL. |

Публичный доступ и HTTPS не настраиваются в этом локальном Compose-профиле. Перед размещением за пределами учебной машины нужны TLS на reverse proxy и отдельные production-реквизиты PostgreSQL.
